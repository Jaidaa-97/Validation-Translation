LHW translation validator

Upload your CONTENT sheet, pick a language, and compare Excel copy to the live hotel page (Playwright).

ESP = Spanish website (code SPA in your Excel column). For hotel spa copy, use a section label like “Spa” / “Wellness” in column A — that loads …/services-amenities/spa.

Leave empty to use the server default URL. When you paste a link, language buttons only swap the host (www, de, jp, …) and keep path + query. If your Excel has dining or spa rows (column A mentions restaurant/dining/spa/wellness, etc.) with text in any language column, the tool opens …/services-amenities/dining and/or …/services-amenities/spa to compare that copy. Labels containing Property Highlight (e.g. “Property Highlight #2 Description”) are matched to the three highlight tiles on the hotel overview (section.property-highlights .highlight-item lead p, with fallbacks). After a run, open Property highlight copy (overview) below to verify what was read. Labels containing Property search open the LHW homepage, search using the hotel name from your pasted /hotel/… (or /property-search/…) URL, then read p.hotel-desc on the results page. Put any text in column H (special note) on a row to compare that row’s expected language cell against the section.property-overview pinned block (not used for Property Highlight or Message banner rows). Use column A label Renovation Notice, Special notice, Message banner, or Hotel message to compare against the overview notice in #main-content div.message (title, body paragraphs, and CTA link text). If dining/spa previews look empty or wrong, start the server from PowerShell with $env:HEADLESS="false"; npm start and/or $env:PW_CHANNEL="chrome"; npm start (uses installed Chrome instead of bundled Chromium).
